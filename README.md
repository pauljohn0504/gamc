# Global AI Mission Community (GAMC) — 첫 번째 실행형 MVP

> **버전:** v0.1.0 · 2026-11-12  
> **형태:** 실제 DB와 세션을 사용하는 웹 애플리케이션 (FastAPI + SQLite + Jinja2 + CSS/JavaScript)  
> **상태:** 로컬 / 비공개 파일럿 운영용. **공개 인터넷 서비스로 배포할 준비가 끝났다는 뜻은 아닙니다.**

## 2. Windows에서 가장 쉽게 실행하기

**준비:** Python 3.11 이상 설치, 인터넷 연결(첫 패키지 설치 시 필요), 빈 폴더에 이 ZIP 압축 해제.

1. `start_windows.bat` 파일을 더블 클릭합니다. 처음에는 필요한 패키지를 설치합니다.
2. 명령 프롬프트에 서버가 시작되면 브라우저에서 **http://127.0.0.1:8000** 을 엽니다.
3. 우측 상단 **회원가입**으로 첫 일반 회원을 만듭니다.
4. 종료하려면 서버 창에서 `Ctrl + C`를 누릅니다.

관리자 계정이 필요하면 **별도 명령 프롬프트**에서 프로젝트 폴더로 이동한 뒤 다음을 실행합니다. 비밀번호는 화면에 표시되지 않게 입력합니다.

```powershell
.venv\Scripts\python.exe manage.py create-admin --email admin@example.org
```

이후 홈페이지에서 생성한 관리자 이메일과 비밀번호로 로그인하면 **운영 관리** 메뉴가 나타납니다. 실사용 이메일을 사용하는 경우 권한이 있는 관리자만 접근하는 안전한 컴퓨터에서 계정을 생성하세요.

> `start_windows.bat` 실행이 막힌 경우, 아래 수동 실행 절차를 사용하세요.

## 3. macOS·Linux 실행 / 수동 실행

```bash
cd GAMC_MVP
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

브라우저 주소: **http://127.0.0.1:8000**

macOS/Linux에서는 `bash start_mac_linux.sh`로도 시작할 수 있습니다.

## 4. 사이트에서 직접 해보는 사용자 시나리오

### A. 신규 회원과 질문 해결

1. 새 회원 A 가입 → `환영합니다`에서 관심 주제 선택.
2. `커뮤니티 → 질문·도움 → 새 글 작성`에서 질문 등록.
3. 다른 브라우저에서 회원 B 가입·로그인 → 회원 A의 질문에 답변 작성.
4. 회원 A가 `내 공간 → 알림`에서 새 답변 확인.
5. 회원 A가 도움이 된 답변의 **해결 답변으로 선택** 버튼 클릭.
6. `검색`에서 질문을 다시 찾아 해결 답변 확인.

### B. 운영자의 콘텐츠와 행사를 실제로 관리

1. `manage.py create-admin ...`으로 관리자를 생성하고 로그인.
2. `운영 관리 → 콘텐츠 관리`에서 자료 또는 행사 생성.
3. 로그아웃 후 공개 `자료실` 또는 `행사`에서 생성된 콘텐츠 확인.
4. 일반 회원이 행사 **참석 신청** 및 **신청 취소** 수행.
5. 관리자가 `콘텐츠 관리`에서 공개 여부를 변경하고 결과 확인.

### C. 협력 프로젝트와 안전한 참여 신청

1. 관리자가 프로젝트 생성.
2. 일반 회원이 프로젝트 상세에서 참여 의사를 입력.
3. 관리자가 `운영 관리 → 프로젝트 신청`에서 확인 및 승인.
4. 신청 회원에게 사이트 알림으로 승인 결과 전달.
5. 공개 페이지에서는 신청 내용·이메일이 보이지 않음.

### D. 신고와 모더레이션

1. 회원 B가 게시글 상세의 **신고하기**에서 사유 제출.
2. 관리자가 `운영 관리 → 신고 관리`에서 신고 사유와 대상을 검토.
3. 운영자가 **종결 / 기각 / 콘텐츠 숨김** 중 선택.
4. 조치 내용은 `감사 기록`에 남음.

## 5. 기술 구조

```text
브라우저 (HTML + CSS + JS, 320px 이상 반응형)
       │ HTTP(S)
       ▼
FastAPI / Jinja2 (Python)
       │
       ├─ 회원 인증 (PBKDF2, 서명 세션, CSRF)
       ├─ Q&A + 해결 답변 + 알림
       ├─ Resources / Events / Projects
       ├─ 신고 접수 + 관리자 권한·감사 로그
       └─ SQLite 데이터베이스 ─ ./data/gamc.sqlite3
```

DB와 세션 비밀키는 실행 시 `./data/`에 자동 생성됩니다. 데이터를 초기화하고 싶으면 **서버 종료 후** `data/` 폴더를 별도 백업하고 새 데이터 폴더로 실행하세요. 실수로 삭제하면 회원과 게시글이 사라질 수 있습니다.

주요 디렉터리:

- `app.py` — 모든 동작의 서버 코드, SQLite 스키마, 라우트와 접근 권한
- `manage.py` — 대화형 관리자 계정 생성
- `templates/base.html`, `templates/page.html` — 화면 템플릿
- `static/styles.css`, `static/site.js` — 반응형 디자인과 최소 인터랙션
- `tests/test_flows.py` — 주요 서비스 흐름 통합 테스트
- `docs/` — 기획서, UX/UI 상세 설계서 (개발 기준)

운영 환경에서 환경변수를 설정할 수 있습니다.

| 이름 | 기본값 | 역할 |
|---|---|---|
| `GAMC_HOST` | `127.0.0.1` | 서버 바인드 주소; 로컬 기본값은 외부 접근 불가 |
| `GAMC_PORT` | `8000` | 수신 포트 |
| `GAMC_DATA_DIR` | `./data` | SQLite DB·서명 키 저장 폴더 |
| `GAMC_SECRET_KEY` | 최초 실행 시 생성·보존 | 서명 쿠키의 비밀키. 실배포 시 비밀 관리자에서 제공 |
| `GAMC_HTTPS_ONLY` | `0` | HTTPS 프록시 환경에 한해 `1` 권장 |

## 6. Docker 실행(선택)

Docker Compose가 설치되어 있다면 다음을 실행합니다.

```bash
docker compose up --build
```

이 설정은 의도적으로 **127.0.0.1:8000**에만 바인드합니다. `http://127.0.0.1:8000`에 접속합니다. 관리자 생성은 다른 터미널에서:

```bash
docker compose exec web python manage.py create-admin --email admin@example.org
```

**공개 인터넷 배포 설정이 아닙니다.** 안전한 HTTPS 리버스 프록시·백업·접근 제어·이메일 인증·운영 정책을 별도로 마련해야 합니다.

## 7. 테스트

```bash
pip install -r requirements-dev.txt
python -m pytest tests/test_flows.py -q
```

검증 내용:

- 회원 가입과 온보딩 / 게시글·답변·해결 상태 / 알림
- 비회원의 회원 전용 글·검색 차단
- 타인이 작성한 질문의 해결 표시 거부
- 관리자만 콘텐츠 등록·권한 변경 허용
- 행사 RSVP 신청·취소 / 프로젝트 신청·승인
- CSRF 토큰 오류 차단
- 본문에 넣은 HTML 스크립트의 자동 이스케이프
- 계정 탈퇴와 로그인 차단
- 데스크톱·모바일 주요 레이아웃의 가로 넘침 미발생 (브라우저 렌더링 검토)

현재 자동화 테스트는 **3개 묶음 테스트**이며, 보안 감사·성능/부하 테스트·전체 접근성/국제화 품질 보증을 대체하지 않습니다.

## 8. 실제 공개 서비스 전에 반드시 해야 할 일

**기술 / 보안**

- [ ] 공식 도메인과 HTTPS 적용, 보안 쿠키 설정 및 리버스 프록시 구성
- [ ] 이메일 인증·비밀번호 재설정·스팸 방지·로그인 시도 제한·MFA(관리자) 구현
- [ ] 데이터 백업·복구 정기 테스트, 배포 후 보안 패치·관찰 체계 구축
- [ ] 서버·DB 접근을 최소 권한으로 제한, 보안 로그와 신고 처리 SLA 확정
- [ ] 인증·권한·CSRF·XSS·동시 요청·개인정보 삭제에 대한 추가 보안 점검
- [ ] WCAG 2.2 AA 접근성 실측, 한국어·영어 UI 완역 및 아랍어 등 향후 지원 검토
- [ ] 저장소 규모가 증가하면 PostgreSQL, 백업·마이그레이션 도입 검토

**운영 / 윤리**

- [ ] 운영 주체, 개인정보 책임자, 연락처, 서버 운영 지역, 보존 기간 및 처리방침 확정
- [ ] 회원/운영자 운영 규칙·검토 프로토콜·이의제기 절차 확정
- [ ] 실제 자료 저작권·출처·라이선스 확인 후 등록
- [ ] 공개 가능한 선교 콘텐츠와 고위험 현장 정보를 구분해 검토
- [ ] 파일럿 첫 20~40명과 함께 소속감·도움 경험의 품질 검증
- [ ] 행사·프로젝트 정보는 실제 승인된 경우에만 게시

> **주의:** 초기 자료실 3개는 이 프로젝트를 위해 새로 작성한 시작 안내와 안전 가이드입니다. 확정되지 않은 행사나 프로젝트는 임의로 생성하지 않았으며, 실제 운영자가 등록할 때만 표시됩니다.

## 9. 기획서와 구현의 연결

- **소속감 / 환대:** 가명 선택, 최소 정보 가입, 관심사 온보딩, 새 질문으로의 자연스러운 연결
- **Social Identity Cycle:** 정체성(홈·소개) → 참여(질문·답변) → 확인(해결 답변·알림)
- **Support + Contribution:** 먼저 질문 해결과 회원의 지식 기여를 중심에 둠
- **Safety:** 로그인한 회원에게만 대화 노출, 공개 페이지에서 민감한 참여 신청 정보 비노출, 신고 및 관리
- **Community lifecycle:** 데이터 없이 시작하므로 소규모 커뮤니티에서 검증 후 확장
- **AI는 보조 도구:** 민감 게시물을 외부 AI 서비스로 자동 전송하지 않음. AI 기능은 P1로 명시적으로 미구현

### 다음 권장 작업 순서

1. 운영팀의 실제 담당자·법적 주체·안전 정책 확정
2. 파일럿 20~40명에게 질문·답변 경험 검증
3. 메일 인증/복구, 스팸 방지, 관리자 MFA 및 외부 배포 인프라
4. 한국어·영어 인터페이스 완역과 다국어 게시물 표시 품질 향상
5. 충분한 동의/정책 아래 AI 번역·AI 검색을 점진적으로 추가

**참고:** 본 앱의 코드와 원본 설계서는 새로 작성한 MVP 산출물입니다. 책의 저작권 콘텐츠를 복제하여 앱에 내장하지 않았습니다.
